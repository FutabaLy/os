FIRST PRINCIPLES

先分清三种关系，再写代码

01

互斥 · 同一时刻只能一个

多人修改同一共享对象，用一把锁保护临界区。先确认是否真的有读写冲突，读与读通常可以并行。

mutex = 1
P(mutex) → 临界区 → V(mutex)

锁住共享操作，不要连准备、计算、消费都锁住。

02

同步 · 这一步必须等那一步

“完成 A 才能做 B”是一条通知。由完成者发出许可，依赖者申请许可。

done = 0
A → V(done) ⇢ P(done) → B

初始为 0 的前提是：事件尚未发生。

03

计数 · 同时可用的名额

空位、产品、座位、碗分别计数。初值直接回答：“开始时有多少个可以申请？”

empty = N − k · full = k
申请名额 P → 使用 → 归还 V

N 为容量，k 为初始已有产品数，不是背死 0 和 N。

记录型信号量：先改数，再判断

P(S) / wait

S.value -= 1
if S.value < 0:
  入等待队列并阻塞

V(S) / signal

S.value += 1
if S.value <= 0:
  唤醒一个等待者

两段都是原子操作。被唤醒者变为就绪，获得 CPU 后从原来 P 的后面继续，不能重新扣一次信号量。

S = −2 表示两个等待者，并不是“欠两个实际物品”。本实验明确采用允许负数的记录型语义。

大题四步法

  1. 列动作有几个角色？每个执行一次还是循环执行？
  2. 画关系共享资源画互斥；先后依赖画箭头；有限数量写容量。
  3. 定含义与初值每个量都用一句话说明“申请的到底是什么”。
  4. 放 P/V，再找反例尝试空、满、先运行后继、多人同时申请的调度。

信号量的账本

S = S₀ + #V − #P

#P 包含已经执行减一但随后阻塞的申请。每次唤醒不再额外减一。

等待数 = max(0, −S)

仅针对本页记录型信号量语义。

有界缓冲区的初值

empty₀ = N − k
full₀ = k · mutex₀ = 1

N 是总容量，k 是初始产品数。并发执行中存在已预订、尚未发布的资源，不能强套 signed empty + full = N。

哲学家与碗

准入 = min(m, n−1)
进餐上限 = min(m, ⌊n/2⌋)

适用于 n≥3 人围桌、n 根相邻共享筷子、m 个碗的题设。准入限制取筷子阶段，进餐上限还受不相邻约束。

交卷前 6 个检查点

  1. 每个信号量都写了含义和初值。
  2. 每个 P 等的资源都有某个 V 会产生。
  3. 放入/取出与 V 的对象没有写反。
  4. 没有拿着对方需要的锁等待对方。
  5. 循环、一轮次数、一次性条件符合题意。
  6. 私有计算移出临界区，没添加多余先后关系。

三句话不能绝对化

“PV 必须在同一进程成对”：互斥锁通常如此；同步通知经常是 A 的 V 配 B 的 P。

“V 的顺序永远无所谓”：必须先完成要发布的数据操作；能否交换还要看锁与可见性语义。

“不死锁就是完全正确”：还需检查容量、通知对象、额外串行化与饥饿条件。
